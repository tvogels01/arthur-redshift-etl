etl.commands module¶

Driver for the ETL based on sub-commands and central place to govern command line args.

This can be the entry point for a console script. Some functions are broken out so that they can be leveraged by utilities in addition to the top-level script.

class etl.commands.FancyArgumentParser(**kwargs)[source]¶

Bases: argparse.ArgumentParser

Fancier version of the argument parser supporting @file to fetch additional arguments.

Add feature to read command line arguments from files and support:

  • One argument per line (whitespace is trimmed)

  • Comments or empty lines (either are ignored)

This enables direct use of output from show_downstream_dependents and show_upstream_dependencies.

Example

To use this feature, add an argument with “@” and have values ready inside of it, one per line:

cat > tables <<EOF
www.users
www.user_comments
EOF
arthur.py load @tables

find_relation_descriptions(args, default_scheme=None, required_relation_selector=None, return_all=False)[source]¶

Most commands need to collect file sets and create relation descriptions around those.

Commands vary slightly as to what error handling they want to do and whether they need all possible descriptions or a selected subset.

If a “required relation” selector is passed in, we first pick up ALL descriptions (to be able to build a dependency tree), build the dependency order, then pick out the matching descriptions.

Set the default_scheme to “s3” to leverage the object store – avoid relying on having current files locally and instead opt for the “publish first, then use S3” pattern.

static location(args, default_scheme=None)[source]¶

Decide whether we should focus on local or remote files.

This returns the appropriate “location” information. This expects args to be a Namespace instance from the argument parser with “table_design_dir”, “bucket_name”, “prefix”, and hopefully “scheme” as fields.

etl.commands.build_basic_parser(prog_name, description=None)[source]¶

Build basic parser that knows about the configuration setting.

The –config option is central and can be easily avoided using the environment variable so is always here (meaning between ‘arthur.py’ and the sub-command).

Similarly, ‘–submit-to-cluster’ is shared for all sub-commands.

etl.commands.build_full_parser(prog_name)[source]¶

Build a parser by adding sub-parsers for sub-commands.

Other options, even if shared between sub-commands, are in the sub-parsers to avoid having to awkwardly insert them between program name and sub-command name.

Parameters

prog_name – Name that should show up as command name in help

Returns

instance of ArgumentParser that is ready to parse and run sub-commands

etl.commands.execute_or_bail(sub_command)[source]¶

Either execute (the wrapped code) successfully or bail out with a helpful error message.

Also measures execution time and does some basic error handling so that commands can be chained, UNIX-style.
